# 崩溃恢复

下次启动自动恢复，不需要先删除正常可读的陈旧 `server.lock`。需要可用的 Python 3.10+，解释器与 `billing.python` 共用。恢复不调用模型、不自动重新执行任务、不自动重发结果。

## 接管规则

1. 先取得数据目录内 `.server.lock.guard` 的操作系统文件锁，串行化竞争启动和释放；进程异常退出会由系统释放这个短期锁。**不要删除 guard 文件**，它存在本身不代表服务仍在运行。
2. 检查 `server.lock` 的 PID 和进程创建标识。只有确认原进程已退出，或 Windows/Linux 确认 PID 已被其他新进程复用，才接管。仅有 PID 的旧格式锁，如果 PID 还在运行，就继续拒绝接管。
3. 原子写入新归属并保存最近一次 `last-recovery.json`。权限不足、锁损坏或无法确认进程状态均停止启动，不猜测、不终止其他进程。
4. 取得独占所有权后，只清理本目录中符合 `state.json.<UUID>.tmp`、`ui-endpoint.json.<UUID>.tmp`、`server.lock.<UUID>.tmp`、`last-recovery.json.<UUID>.tmp` 格式的普通文件，以及属于旧服务的 UI 连接记录。不递归清理，不跟随目录联接，不删除会话、凭据、模型配置或账本。

新服务与旧版服务争用原本不存在的锁时也采用独占发布，避免覆盖旧版刚创建的锁。建议同一数据目录统一使用新版。目录应位于本机文件系统；网络共享盘的锁与持久化语义未验证。

## 状态与费用

`state.json` 每次先写临时文件并刷新到磁盘，再原子替换；失败时保留上次完整文件。它降低进程崩溃导致状态损坏的风险，不承诺断电或硬盘故障时绝对不丢数据。

运行中的任务恢复为 `interrupted`，请求暂停的恢复为 `paused`，保留消息队列，等待明确的继续指令。结果不明的回传变为 `unknown`，避免重复发送。未收到完整计费回执的调用保留整笔预留费用，不自动退款；仍需人工核对，尚无 UI 对账解锁入口。

正常关闭时，即使某一步清理报错，也继续尝试关闭 UI 连接、计费网关、子代理控制桥和临时配置；无法确认子代理退出时仍保留占用，不宣称已安全清理。

## 边界

此版本不按进程名批量杀死 Node、Electron 或 Python。宿主意外退出后，旧工作进程无法再通过已经消失的宿主网关发出新的付费请求；已经送达供应商的请求仍可能产生费用。Harness 自身负责 SDK 连接关闭后的退出。任意工具自行分离启动的后台进程，尤其长时间运行的外部脚本，尚不保证自动回收；恢复后遇到文件占用或持续写入，应核对对应任务进程。

锁文件损坏时，应保留现场并确认原服务与工作进程已经退出后再处理。不能通过删除 `state.json`、清空费用或解除未知预留来“修复”崩溃。
